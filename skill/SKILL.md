# 面试复盘

工具代码在 interview-review 仓库（安装脚本会把本 skill 软链到 `~/.claude/skills/interview-review`），命令行是 `interview`（录音 / 导入 / 转写，全部本地运行），数据在 `~/Interviews`（设置了 `INTERVIEW_HOME` 环境变量时以它为准，下文的 `~/Interviews` 都按它替换）：

```
~/Interviews/
  2026-10-19_1530_示例公司-后端-一面/
    interviewer.m4a  me.m4a      # 双轨录音（或导入的 mixed.m4a）
    transcript.md / .json        # 对话稿
    context.md                   # 公司/岗位/轮次/JD（可选）
    report.md                    # 本 skill 产出
  _profile/resume.*              # 简历 .md/.txt/.pdf（可选，让"更好的答法"有据可依）
  _bank/questions.md             # 题库（跨场次）
  _bank/weaknesses.md            # 弱项档案（跨场次）
```

## 1. 找到要复盘的那场

- 参数是目录：用它。
- 参数是音视频文件：`interview import <文件> [公司-岗位-轮次]`，它会转写并打印 `下一步：… <目录>`，用那个目录。
- 没参数：`interview ls`，取最新一场（第一行）。
- 状态是"仅录音"：先 `interview transcribe <目录>`（本地跑，1 小时录音几分钟，用 Bash 时 timeout 给足 600000）。
- 已有 report.md：问用户是看旧报告还是重做。

## 2. 收集上下文（缺了也不阻塞）

只读会话目录和 `~/Interviews` 下的文件，不需要看工具源码。


1. 完整读 `transcript.md`（长就分段读完，不能只看开头）。
2. `context.md`：没有的话从目录名推断公司/岗位/轮次；推断不出就用一句话问用户，顺便问有没有 JD。用户没给就继续。拿到的信息写进 `context.md`。
   - 从「面试复盘」App 后台调用时（提示里会说明），用户看不到对话：**不要提问**，缺什么直接跳过。
3. `~/Interviews/_profile/resume.*`（.md / .txt / .pdf）：有就读。没有就在回复末尾提醒一次"在 App 左下角设置简历，更好的答法会更贴你的经历"。
4. `~/Interviews/_bank/weaknesses.md`：有就读，用来判断这次是不是老问题又犯了。

## 3. 分析原则

- **只依据对话稿**。引用原话带时间戳 `[hh:mm:ss]`，不要编造对话里没发生的内容。
- **转写错字不算我的错**：同音字、英文术语识别错（如 "readds/radis"→Redis，"热点可"→热点 key，"AYS位"→MySQL）按上下文还原后再评价；实在判断不了的标【听不清】。
- **单轨录音的说话人可能归错**（transcript.md 头部"说明"会写）：按内容纠正，并在报告开头注明。
- **更好的答法不替我编经历**：只用对话稿和简历里出现过的事实；需要我补的具体数字/细节用【补充：…】占位。
- **技术题核对对错**：答错的指出错在哪并给正确说法；答对但浅的，指出缺了哪一层（原理 / 取舍 / 边界条件 / 线上数据 / 踩过的坑）。
- **直说问题，不客套**。评分要有区分度：5 超出预期，4 扎实，3 及格但普通，2 明显欠缺，1 答错或没答上。
- **⚠️ 录音缺口**：对话稿里标了"录音缺口"的那段没录到。缺口前后的话不连续，不要把缺口后的回答当成对缺口前问题的回答，也不要因为缺口里"没说话"扣分；在报告开头说明缺口位置。
- **🚩 标记必须回应**：对话稿里的 🚩 是我面试时按快捷键标的（觉得没答好 / 想重点复盘）。标记附近那道题要单独深入分析，并在报告里「你标记的时刻」一节逐个回应：当时发生了什么、问题出在哪、下次怎么答。
- **读面试官信号**：对同一点连续追问（没拿到想要的 / 想挖深）、打断、"好的，那我们换个问题"（通常是放弃这个点了）、主动给提示、介绍团队时的投入程度、各环节时间分配。

## 4. 怎么切题

- 一道题 = 面试官发起的一个话题 + 它的追问链；追问挂在主问题下（Q2.1、Q2.2）。
- 每题标类别：自我介绍 / 项目深挖 / 基础知识 / 系统设计 / 算法与代码 / 行为与动机 / 反问。
- 写代码环节对话稿里只有口头部分：只评价思路表达和沟通，提醒用户补充当时写了什么、有没有跑通。

## 6. 沉淀到题库和弱项档案

- `~/Interviews/_bank/questions.md`：没有就新建，表头 `| 日期 | 公司-岗位-轮次 | 类别 | 题目 | 得分 | 报告 |`。每道主问题追加一行，题目改写成可复用的通用问法，报告列写相对路径链接。
- `~/Interviews/_bank/weaknesses.md`：按弱项归类（如"缺量化数据""高并发只会背概念""项目难点讲不出取舍"）。每条记：出现次数、最近日期、一个例子（链到报告）。这次又犯的次数 +1；明显改善的标"已改善"并写在哪场。

## 7. 回复用户

- 3～6 行：整体分、一句话结论、最该改的 3 件事、报告路径。不要把整份报告贴进对话。
- 最后问一句要不要针对最弱的题做模拟练习。用户要的话，你扮演面试官问这道题和追问，用户回答后按同一套标准点评，再给示范。

## 隐私

录音、对话稿、报告都只存在本机。除非用户明确要求，不要发布成 artifact，也不要上传飞书或其他云文档。
